How it works

Real LLMs, running inside Internet Computer canisters — no off-chain API, fully verifiable.

In-canister LLMs

Each model is deployed as a smart contract using llama_cpp_canister (llama.cpp on the Internet Computer). The gguf weights are uploaded into the canister's stable memory, loaded into working memory, and inference runs on-chain. Because the Internet Computer caps the work per message, a reply is produced across a sequence of update calls — the app streams each batch of tokens to you as it arrives.

The studio

  • Model switch. Pick a model from the dropdown; each is a separate on-chain canister. Switching starts a fresh conversation.
  • System prompts. Use the default persona or open the editor to write and save your own prompt slots. The system prompt shapes every reply in a conversation.
  • Live stats. A conversation shows turns, in-canister calls, approximate tokens in/out, tok/s, and the exact cycle cost.

Exact cost & speed, measured in-canister

All inference is routed through a single controller canister (icgpt_admin), which is the only caller allowed to reach the model canisters. Because it is the sole caller, it measures each call precisely: it reads the model canister's live cycle balance right before and after the call (and brackets the IC system time) to report the exact cycle cost and exact tok/s — excluding network round-trips and the controller itself.

Isolation & concurrency

Every user's conversation lives in its own prompt-cache file inside the model canister, keyed by their principal — so no one can read or affect anyone else's chat. A single model canister serves many users by time-sharing one compute buffer, swapping each user's cache in and out per request. The design is safe under concurrency; the ceiling is throughput (one inference per model canister at a time).
