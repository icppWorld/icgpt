ICGPT — On-chain Prompt Studio

Optimize your prompts against LLMs running inside Internet Computer canisters — on-chain in the most literal sense: in-canister.

ICGPT is a studio for designing, testing, and refining prompts against real large language models that run entirely on-chain. There is no call out to an off-chain API: the model weights live in a canister's stable memory and every token is generated by in-canister compute, verifiably, on the Internet Computer.

What you can do

  • Optimize a repeating task in the Prompt Cost Lab. Design a templated prompt, sweep its variables, and read the exact per-request cost and quality — then compare configurations to find the cheapest one that still passes. See Prompt Cost Lab.
  • Chat with on-chain models. Switch between five models — from Gemma-3-270M to Qwen3-1.7B — each served from its own canister, and design your own system prompts.
  • See exact economics. Every request reports the exact in-canister cycle cost and generation speed (tok/s), measured on-chain by the controller.

How it runs on-chain

Each model is deployed as a smart contract using llama_cpp_canister (llama.cpp on the Internet Computer). The gguf weights are uploaded into the canister's stable memory, loaded into working memory, and inference runs on-chain. Because the Internet Computer caps the work per message, a reply is produced across a sequence of update calls — the app streams each batch of tokens to you as it arrives.

Exact cost & speed, measured in-canister

All inference is routed through a single controller canister (icgpt_admin), which is the only caller allowed to reach the model canisters. Because it is the sole caller, it measures each call precisely: it reads the model canister's live cycle balance right before and after the call (and brackets the IC system time) to report the exact cycle cost and exact tok/s — excluding network round-trips and the controller itself.
