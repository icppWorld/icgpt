Parameters

Turn ICGPT into a real experimentation studio: tune exactly how the model samples each reply, then compare the results side by side.

Alongside the system prompt, the Parameters panel exposes the model's sampling and inference settings — temperature, sampling cut-offs, penalties, response length, a thinking toggle and a seed. Every setting is applied to your very next generation, so you can change one knob and immediately see the effect.

Opening the panel

Click ⚙ Params in the toolbar at the top of the studio (next to ⚙ System).

Changes are live. Sampling settings apply to the next generation with no need to start a new chat — so you can edit a value and re-send the same prompt to compare. Your settings are remembered per browser and apply to every conversation until you change or reset them.

Settings

Temperature

Creativity vs. obedience. Lower values (0.4–0.6) keep the model focused and reliable for instructions; higher values make it more varied and surprising.

Max response length

A cap on how many tokens the reply may use. Because the reply is generated across a sequence of on-chain update calls, a larger cap means more calls — and therefore more time and cycles. The cap is approximate: the canister does not report an exact token count, so ICGPT estimates it and stops the reply once the estimate is reached.

Thinking mode Qwen3 only

Qwen3-0.6B is a hybrid thinking model. With thinking off (the default) it answers directly. Turn it on and the model reasons through the problem first, then answers — more thorough, but slower and more tokens. Qwen2.5-0.5B has no thinking mode, so the toggle is disabled when it is selected.

Seed

Leave the seed on 🎲 Random for fresh variety each run, or lock it to a number to make a run more repeatable while you tweak the prompt. Because a reply is produced across many update calls over a shared prompt cache, treat a locked seed as best-effort reproducibility, not a hard guarantee.

Sampling

The collapsible Sampling section holds the finer knobs that shape the token distribution the model draws from.

  • min_p — drops tokens below a minimum probability (relative to the top token). 0 disables it.
  • top_p — nucleus sampling: consider only the most likely tokens whose probabilities sum to this value.
  • top_k — consider only the k most likely tokens. 0 turns it off.
  • repeat_penalty — penalizes tokens that have already appeared, to curb repetition. 1.0 is no penalty.
  • repeat_last_n — how many recent tokens the repeat penalty looks back over.
  • Stop sequences — one per line. Generation halts as soon as the output produces any of them.

Advanced

  • presence_penalty — a flat penalty for reusing any token that has appeared, encouraging new topics. 0 disables it.
  • frequency_penalty — scales the penalty by how often a token has appeared, curbing over-used words. 0 disables it.
